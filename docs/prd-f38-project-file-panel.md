## 2. 产品目标

工作台当前是「左侧栏 + 中间对话流 + 底部输入区」三块，**没有右侧面板**。用户在会话里让 Agent 改了十几个文件后，只能回到终端 `git status` / 打开编辑器才能知道「改了什么、改成什么样」；也让「我想先看看项目里有什么」这件事必须离开产品。本期新增右侧可折叠面板，把**项目文件树**与**工作区变更清单**收进产品内，做到「不离开会话就能看见、能读，但不改」。

| # | 目标 | 衡量标准 |
|---|---|---|
| G1 | 面板化：右侧面板承载「文件 / 变更 / 文件预览」三类标签，开合一处可达 | 顶栏一个按钮开合；面板宽度可拖拽并在刷新后保持；标签切换 ≤ 1 次点击 |
| G2 | 只读可见性：不依赖编辑器即可浏览项目结构与文件内容 | 任取一个 Markdown 文件，从点开树到看到渲染结果 ≤ 2 次点击；超大/二进制文件给出明确降级提示而非白屏 |
| G3 | 变更可见：一个面板里同时看到「改了哪些文件、各改了多少行、单个文件具体怎么改的」 | 变更清单行数与 `git status` 一致（含未跟踪）；顶部合计 = 各行 +N/-M 之和；点行即见该文件 diff |

**与 WorkBuddy 对齐的定位**：同结构（右侧折叠 + 标签条 + 文件树/变更/预览），同信息密度（24px 行高、类型图标彩色、绿加红减）；**不同边界**——我们不提供文件编辑、不提供终端，定位为「只读观察窗」，写操作仍由 Agent 与会话流承担。

## 3. 用户故事

| 编号 | 角色 | 故事 | 验收标准 |
|---|---|---|---|
| US-38-1 | 开发者 | 我想在会话旁边展开项目目录树，快速确认某个目录里到底有什么文件 | 面板「文件」标签展示树形目录；点文件夹按需拉取子层（懒加载）；含 `.github`/`.workbuddy` 等点号目录也可见 |
| US-38-2 | 开发者 | 我不想切到编辑器，直接在面板里读 Markdown 方案稿和代码 | 点文件打开独立预览标签：Markdown 正常渲染标题/表格/引用块，代码带高亮；图片可直接查看 |
| US-38-3 | 开发者 | Agent 说「已修改 8 个文件」，我想一眼核对这些文件与改动量 | 「变更」标签列出工作区全部变更文件（含未跟踪），每行绿 `+N` 红 `-M`，顶部显示合计 |
| US-38-4 | 开发者 | 我想在提交前确认某个文件到底改了什么 | 点变更行 → 面板下方展示该文件 unified diff，新增行绿底、删除行红底，带行号与 hunk 头 |
| US-38-5 | 开发者 | 我不希望面板每次都占用屏幕，也不希望每次都要重新拉宽 | 顶栏按钮开合面板；拖拽边缘调宽；开合状态与宽度刷新后保持；切换项目时树根跟随切换 |
| US-38-6 | 团队 / 安全视角 | 我只允许产品读取**当前项目根之内**的文件，任何越界路径必须被拒绝 | 传入 `../`、绝对路径、指向根外的符号链接一律拒绝（4xx）；端点全部只读（无任何写方法） |

| F-38-3 | 面板空态动作区 | 面板首次打开、未选中任何标签时，正文垂直居中排列动作：**打开浏览器**（在系统文件管理器中打开项目根，复用既有 reveal 能力）/ **查看工作空间**（切到「文件」标签）/ **查看变更**（切到「变更」标签）/ **打开终端**（本期范围外，P0 隐藏该按钮，见 Q2）。动作项为整行按钮，hover 用 `--bg-hover` |
| F-38-4 | 文件树 | 「文件」标签渲染当前根的目录树：① **点文件夹才拉子层**（懒加载，首次展开显示 skeleton，已加载的层缓存不再请求）；② 文件夹前 chevron（`▸/▾`，10px），文件前为按扩展名着色的类型图标；③ 排序：目录优先，同类按名称字典序（不区分大小写）；④ 行高 24px，每层缩进 12px，13px 字号，超长名省略号 + `title`；⑤ **点号目录照常展示**（`.github`、`.workbuddy`、`.vscode` 等），但忽略重量级目录（清单见 §6）；⑥ 只读：无右键菜单、无拖拽、无新建 |
| F-38-5 | 文件预览 | 点文件在面板内打开/复用预览标签。头行 40px：文件名 + `📋 复制`（复制文件内容，Markdown 复制原文）+ `⋯ 更多`（P0 仅含「复制相对路径」「在文件管理器中显示」）。正文按类型分流：**Markdown** 用既有 `renderMarkdown`（markdown-it + DOMPurify，与消息流同口径）；**代码**用 highlight.js 高亮 + 行号（只读 `<pre>`）；**图片**（png/jpg/svg/webp/gif）直接渲染；**其它/二进制/超大** 显示降级提示卡（「该文件为二进制或超过 1MB 上限，无法预览」+ 文件大小 + 完整路径），不做下载 |
| F-38-6 | 变更清单 | 「变更」标签数据源 = **git 工作区状态（`git status` 口径，包含未跟踪文件）**。头部汇总行：「文件变更」+ 绿 `+N` + 红 `-M` + 刷新按钮 ⟳。列表每行 24px：类型图标 + 相对路径（过长省略）+ 绿 `+N` + 红 `-M`；未跟踪文件以新增语义展示（`+N` 为全文件行数，`-0`）。上限 300 行，超出底部提示「已截断，共 N 个文件」。非 git 仓库 → 正文空态（见 F-38-8）。**不提供**暂存/提交/回滚按钮 |
| F-38-7 | 单文件 diff 详情 | 「变更」标签内部上下分栏：上部变更清单（最大 50% 高，独立滚动），下部详情区。点击某行 → 加载该文件 unified diff 并高亮选中行（`--bg-active`）；详情头显示相对路径 + 复制 + `×` 清除选择。diff 渲染：hunk 头 `@@` 用 `--text-faint`；新增行 `--green-soft` 底色 + 绿行号；删除行 `--red-soft` 底色 + 红行号；等宽字体。未选中任何行时详情区显示空态文案「**请选择一个产物查看详情**」。超大 diff 截断（见 §6） |
| F-38-8 | 状态与错误态 | 三态齐备：**加载态**（树/清单 skeleton 行、预览区「加载中…」）；**空态**（空目录「该目录为空」；变更清单为空「工作区无未提交变更」；未选会话/未选项目「请先在左侧选择一个项目」）；**错误态**内联卡片（非 git 仓库「当前目录不是 git 仓库，无法查看变更」、文件已删除「文件已不存在，可能已被删除或移动」+ 关闭该标签、权限不足「无权限读取该路径」、请求失败「加载失败，点击重试」）。错误不弹全局 toast 打断会话 |
| F-38-9 | 只读后端能力 | 新增只读端点（路径与响应形态由架构师定义，PRD 只约束能力）：列目录（返回条目名/类型/是否目录，**不返回根外绝对路径**）、读文本文件、读取变更汇总、读取单文件 diff。全部仅 GET；路径参数一律视为**相对项目根**；无任何写方法 |
| F-38-10 | 与工作根/项目切换联动 | 面板数据根默认 = **当前会话工作根**（F-37：绑定 worktree 时即 worktree 目录，与 `GitStatusBar` 显示的分支/目录保持一致）；无会话时 = 当前选中项目根。切换项目 / 切换分支 / 勾选 worktree 后：文件树与变更清单整体失效重拉、已打开的动态标签全部关闭（避免展示旧根内容）。变更面板在会话运行结束（`running: true → false`）时自动刷新一次 |

## 6. 安全与性能边界（写死，需在实现与测试中体现）

| 边界 | 规则 |
|---|---|
| 路径穿越 | 所有路径参数按**相对项目根**解析，解析后必须仍在根内（含 `..` 折叠与符号链接真实路径校验）；`..` 越界、绝对路径、根外 symlink 一律 4xx。**任何符号链接不跟随**（沿用现有 `collectProjectFiles` 的 `isSymbolicLink()` 跳过策略） |
| 根外信息泄漏 | 响应只返回相对路径；错误信息不回显根外绝对路径 |
| 单文件读取 | 上限 **1MB**（对齐既有 `MAX_SNAPSHOT_BYTES = 1_000_000`）；超限返回 size + 降级提示，不截断返回半截内容 |
| 二进制判定 | 前 8KB 含 NUL 字节判定为二进制 → 不返回内容，仅提示（沿用 `readSnapshot` 探测口径） |
| 目录条目 | 单层条目上限 **500**，超出返回 `truncated: true` 并在 UI 提示「仅显示前 500 项」 |
| 树深度 | 单次展开不限层数（逐层请求天然受限），但 UI 缩进最多 12 层后不再叠加（防横向溢出） |
| 变更清单 | 上限 **300 个文件**，超出截断并提示总数 |
| 单文件 diff | 上限 **2000 行 / 256KB**，超出截断并提示「diff 过大已截断，建议在终端查看」 |
| 端点耗时 | 单次请求目标 ≤ 3s；超时返回已收集部分 + `truncated`，不返回 500 |
| 并发 | 树节点重复展开走前端去重（同一路径在飞行请求合并），不重复打后端 |
| 只读保证 | 端点无写方法；面板内无任何编辑/暂存/提交入口（本期） |

**目录显隐规则**（与现有 `GET /api/projects/:id/files` 的差异，架构师注意：该端点跳过**所有**点号目录，不能直接复用）

| 类别 | 目录 |
|---|---|
| **必忽略**（不可见） | `node_modules`、`.git`、`dist`、`build`、`out`、`coverage`、`target`、`__pycache__`、`.venv`、`venv`、`.next`、`.nuxt`、`bin`、`obj` |
| **必须显示**（点号目录照常展示） | `.github`、`.workbuddy`、`.vscode`、`.idea`、`.config`、`.claude`、`.delta` 以及任何其它点号目录 |

## 10. 验收要点（抽查清单）

1. 顶栏按钮开合面板；调宽后刷新页面，宽度与开合状态保持（localStorage 键值正确）。
