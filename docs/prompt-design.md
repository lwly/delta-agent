# delta-agent Prompt 组装设计（静态 / 动态 / 模式切换）

> 版本：v1.0 ｜ 日期：2026-10-21 ｜ 参考：PaiCLI Prompt 拼装方案 ｜ 关联：technical-design.md §5、memory-design.md §7、agent-modes-design.md

## 1. 总览：一个完整 Prompt 是怎么拼出来的

```
静态 Prompt（稳定内容，可缓存复用）          动态 Prompt（每轮更新）
├─ 人格（Identity）                         ├─ 当前时间 / 运行环境快照
├─ 行为准则（Environment 基线）             ├─ 模型信息（当前模型/能力/上下文窗口）
├─ 项目指令（Project + 静态记忆 + 工具）     ├─ 记忆（L2 召回 Top-K）
│                                          └─ Skill 索引（+已加载缓冲区内容）
│          │
│          ▼
│   ┌──────────────────┐
│   │ 缓存复用          │   命中 → 直接复用组装结果
│   │                  │   未命中 → 重新组装并更新缓存
│   └──────────────────┘
│          │
│          ▼
│   ┌──────────────────┐
│   │ Prompt Builder    │   组装 · 去重 · 裁剪 · 格式化
│   └──────────────────┘
│          │
│          ▼
│   模式提示词（模式切换，最后追加）
│   ├─ 📋 Plan 模式
│   ├─ ⚡ ReAct 模式
│   └─ 🤖 Team(Multi-Agent) 模式
│          │
│          ▼
│         LLM
```

> 口诀：**稳定内容复用缓存，动态信息按轮注入，模式提示最后切换。**

## 2. 静态 Prompt（稳定内容，可缓存复用）

### 2.1 内容构成（映射 7 层架构）

| 段 | 来源层 | 内容 | 变更时机 |
|----|--------|------|----------|
| 人格 | L1 Identity | Agent 身份、安全基线（locked，不可覆盖） | 随版本 |
| 行为准则 | L2 Environment | 输出规范、工具使用纪律、确认策略 | 随版本 + 平台探测 |
| 项目指令 | L3 Project | README 摘要/目录结构/技术栈/规范 + **L3 静态记忆**（MEMORY.md/.delta/agent.md） | 项目文件/git 变更 |
| 工具清单 | L4 Tools | 内置 14 工具 + MCP 动态工具的 schema | 工具/MCP 注册变化 |

### 2.2 缓存复用策略（双层）

**① 应用层组装缓存**（自己控制）：

```typescript
interface StaticPromptCache {
  key: string;        // hash(层内容 + 组装器版本 + 覆盖集指纹)
  value: string;      // 组装好的静态 Prompt 全文
}
// 命中：key 相同 → 直接复用，O(1)
// 未命中：重新组装受影响层 → 更新缓存
```

**② Provider Prompt Cache 对齐**（省钱提速）：
- 静态 Prompt 恒定放在 messages 最前部，作为 Anthropic `cache_control` / OpenAI 自动前缀缓存的稳定前缀
- 静态 → 动态 → 历史 → 本轮输入 的顺序永不改变，保证前缀可命中
- 收益：重复轮次输入 token 按缓存价计费（Anthropic 最高 9 折/命中 10%），首字延迟显著降低

### 2.3 缓存失效时机

| 触发 | 影响段 | 动作 |
|------|--------|------|
| MCP 工具注册/断开 | 工具清单 | 仅重组装 L4 |
| Skill 加载/卸载 | （索引在动态段，不受影响）；项目级 Skill 变更 | 无需重组装静态段 |
| `.delta/` 配置或 MEMORY.md 变更 | 项目指令 | 仅重组装 L3 |
| 版本升级 / 覆盖集变化 | 全部 | 全量重组装 |

## 3. 动态 Prompt（每轮更新）

| 段 | 内容 | 更新频率 |
|----|------|----------|
| 时间与环境 | 当前时间、CWD、git 分支状态 | 每轮 |
| 模型信息 | 当前模型名、上下文窗口、剩余预算 | 每轮（配置变更时） |
| 记忆 | L2 动态记忆召回 Top-K（memory-design §5 评分），含已采纳待生效 | 每轮重新召回 |
| Skill 索引 | name + description + 触发词（轻量常驻）；**已加载 Skill 的完整内容**（跨轮次缓冲区）随注入更新 | 加载/卸载时 |

动态段紧跟静态段之后拼装，**不破坏缓存前缀**（动态段在静态段之后，历史消息之前）。

## 4. Prompt Builder（组装 · 去重 · 裁剪 · 格式化）

```typescript
interface PromptBuilder {
  build(ctx: AssembleContext): FinalPrompt;
  // 1. 组装：静态段(缓存复用) + 动态段(每轮) → 有序 section 列表
  // 2. 去重：记忆/项目指令/Tool 描述间重复内容按"更具体来源优先"合并
  // 3. 裁剪：超预算时按优先级丢弃（见下）
  // 4. 格式化：统一 Markdown section 结构（<static>…</static><dynamic>…</dynamic>）
}
```

**去重规则**：同一事实出现在静态项目指令与召回记忆中 → 保留静态版，记忆条标记 deduped（仍计访问）；工具与 MCP 能力重叠 → 提示词中声明优先级。

**裁剪优先级**（预算不足时从低到高保）：Skill 索引描述 > 低分记忆 > 高分记忆 > 动态环境 > 静态核心段（人格/准则/工具 schema 永不裁剪）。

**token 预算分配示例**（200k 窗口）：

| 段 | 预算 | 说明 |
|----|------|------|
| 静态 Prompt | ≤ 8k | 人格+准则+项目+工具 schema |
| 动态 Prompt | ≤ 2k | 时间/模型/环境 |
| 记忆 Top-K | ≤ 1.5k | 5 条 × 300 |
| Skill 已加载 | ≤ 4k（可配） | 超出提示 unload 或分页读取 references |
| 会话历史 | 其余 | 压缩器托管（80%→55%） |
| 安全预留 | 1024 | 系统与回复 |

## 5. 模式提示词（最后追加，切换不动缓存）

| 模式 | 提示词要点 |
|------|-----------|
| 📋 Plan | 先产出 DAG 计划并等待确认；按层执行；汇报节点状态 |
| ⚡ ReAct | 单步循环决策；工具优先；观察后再行动 |
| 🤖 Team | 角色/工作池说明；节点隔离上下文规则；结果回传格式 |

- 模式段**始终位于 Prompt 末尾**：切换模式只替换最后一小段，静态缓存前缀完全不动
- 多模式参数（如 maxTurns、并行度）随模式段一并提供

## 6. 调试与可观测

- `--debug-prompt` / Web"查看本次 Prompt"：导出最终拼装结果（标注各段来源、token 数、缓存命中状态）
- 每轮记录 `prompt_sections` 日志：静态段 hash、命中与否、动态段 token、裁剪明细——用于调优预算分配
