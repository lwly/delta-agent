# PRD F-22b：定时任务 Web 端全栈改版（对齐 WorkBuddy 模式）

> 状态：草案 v1 · 2026-06 · 依赖 F-22（定时任务内核 + CLI + Web 面板已交付，见 design-f22-cron.md）
> 本文档为**增量 PRD**，只描述变更部分；F-22 已有内容（数据模型基础、cron 解析、执行器框架、现有 API 端点）不再重复。

## 1. 变更目标

1. **G1 体验对齐 WorkBuddy**：Web 定时任务从「工程师式表单」升级为「任务卡片 + 人性化控件」，让不熟悉 cron 语法的用户也能创建/管理定时任务。
2. **G2 能力补齐**：后端新增任务级有效期（validFrom/validUntil）与权限模式（permission），使 Web 面板可完整表达运行语义，且与 CLI 共用同一 `cron.json` 存储（version 1 → 向后兼容升级）。
3. **G3 向后兼容**：CLI 创建的原始 cron 表达式任务在 Web 列表可读（人话化描述或原样展示）、可编辑（回填自定义 cron 模式）。

## 2. 用户故事

1. 作为普通用户，我想用「每天 / 每周一 / 每月 1 号 + 时间」这样的下拉控件创建定时任务，而不是学写 cron 表达式，这样我能 30 秒内建好任务。
2. 作为普通用户，我想在卡片上看到「每天 09:00」和「11 小时后执行」这样的人话描述与倒计时，这样我一眼知道任务何时会跑。
3. 作为注重安全的用户，我想为每个任务单独选择权限（标准确认 / 允许完全访问 / 只读），这样高权限只授予确实需要的任务。
4. 作为有周期性项目（如两周冲刺）的用户，我想给任务设「自定义起止日期」有效期，过期自动不再执行，不用记得手动停用。
5. 作为同时管理多个任务的用户，我想用批量管理一次启用/停用/删除多个任务，而不用逐个点开关。

## 3. 现状核实（影响后端范围的结论）

| 项 | 现状 | 结论 |
|---|---|---|
| `delta run --permission` | **已支持**（F-23：plan/default/yolo，yolo 须与 `--yolo` 双重开启） | 无需改 headless-run.ts，只需执行器透传 |
| `cron-executor.ts` | 仅透传 `-p/--json/--max-cost`，**未传 permission** | P0：需在 spawn args 中追加 `--permission <mode>`；mode=yolo 时同时追加 `--yolo` |
| 有效期 validFrom/validUntil | 数据模型无此字段，runner 无窗口判断 | P0：store + runner + API 三处增量 |
| cron.json | version: 1 | P0：缺字段视为长期有效/标准确认（向后兼容），version 升 2 或保留 1 + 可选字段（实现时二选一，倾向后者，见待确认 Q3） |

## 4. 需求池

### P0（本期必做，已确认范围）

- **后端-数据模型**：CronJob 新增 `permission?: 'plan' | 'default' | 'yolo'`（缺省 'default'）与 `validFrom?: ISO / validUntil?: ISO`（缺省长期有效）；store CRUD 支持；原子写口径沿用 F-22。
- **后端-runner**：到期判定增加有效期检查——`now < validFrom` 或 `now >= validUntil` 时**仅静默跳过执行，nextRunAt 仍按 cron 表达式正常推进**（保持 cron 相位，窗口结束后自然恢复）；手动补跑（onlyJobId / POST run）不受有效期限制，仍可强制试跑。
- **后端-执行器**：cron-executor 透传 `--permission`；yolo 需 `--permission yolo --yolo` 双 flag（沿用 F-23 resolvePermissionMode 语义，防止单 flag 降级告警）。
- **后端-API**：POST /api/cron 与 PATCH /api/cron/:id 接受 `permission` / `validFrom` / `validUntil`；非法值 400（permission 枚举校验、日期 ISO 解析校验、start<=end 校验）。
- **前端-列表页改版**：顶部 Tab 筛选（全部 N / 已启用 N / 已暂停 N，带计数）；任务卡片重排——标题行 = 任务名 + 右侧 toggle 开关；正文 = prompt 两行截断预览；底部行 = 左侧「🔁 每天 09:00」人话化调度描述 + 右侧「N 小时后执行」下次运行倒计时；卡片操作 = ▶ 立即运行 / ✎ 编辑 / … 更多（删除，二次确认沿用）/ toggle。
- **前端-人话化调度描述**：内置 cron → 中文描述转换（每小时/每天 HH:MM/每周 X HH:MM/每月 X 日 HH:MM/每 N 分钟步进等常见模式）；无法识别的表达式原样展示等宽字体代码样式（兼容 CLI 创建任务）。
- **前端-新建/编辑弹窗**：
  - 任务名称（单行，必填，唯一由后端校验）
  - prompt 大号多行输入（必填）
  - 工具行 1：工作空间下拉（映射 cwd，候选取 serve 已知项目目录列表 + 手动输入路径兜底）+ 权限下拉（标准确认=default / 允许完全访问=yolo / 只读=plan，默认标准确认）
  - 工具行 2：重复下拉（每小时/每天/每周/每月/自定义 cron）+ 时间 HH:MM 选择 + 每周附星期几多选、每月附几号选择 + 有效期（长期有效 / 自定义起止日期）
  - 自定义 cron 模式：直接填 5 字段表达式，前端即时调用后端校验（或复用解析错误信息展示）
  - 编辑态：任务为标准模式 cron 时控件回填为对应下拉；非标准 cron 回填自定义模式
- **前端-倒计时**：next_run_at 相对当前时间的「N 分钟/N 小时/明天/N 天后执行」，分钟级自刷新。

### P1（Should have，**本期做**）

- 调度描述国际化（i18n）。
- 卡片拖拽排序 / 自定义分组。
- 更多人性化重复选项（每 N 天、工作日组合、多个时间点）。
- Web 端展示/编辑 maxCostUsd（保留字段透传，UI 本期不重点做，弹窗可隐藏在「更多设置」）。

## 5. 交互要点说明

### 5.1 列表页

- Tab 计数实时随数据变化；「已暂停」即 enabled=false。
- Toggle 开关直接切换 enabled（PATCH），失败回滚 UI 并 toast 错误。
- 「11 小时后执行」倒计时基于 next_run_at；任务已过期未跑（daemon 停机）时显示「待补跑」。
- 有效期已过（now > validUntil）的任务：卡片底部调度描述旁加「已过期」灰色徽标；toggle 仍可操作但 runner 不再执行（展示口径见验收）。
- 删除沿用现有两次点击确认交互；编辑按钮打开与新建相同的弹窗（预填当前值）。

### 5.2 新建/编辑弹窗字段校验

| 字段 | 规则 |
|---|---|
| 任务名称 | 必填、非空；后端唯一性校验冲突时展示 400 message |
| prompt | 必填（trim 后非空） |
| 工作空间 cwd | 必选/必填；必须是绝对路径（前端提示 + 后端沿用现有目录校验，运行时目录不存在收敛 error 记录） |
| 权限 | 枚举三选一，默认 default；选「允许完全访问」时下拉旁出现一行黄色提示「该任务将无需确认执行所有操作」 |
| 重复 = 每小时 | 不出现时间选择；cron = `0 * * * *`（整点；P2 支持分钟偏移） |
| 重复 = 每天 | 必选 HH:MM；cron = `MM HH * * *` |
| 重复 = 每周 | 必选 HH:MM + 至少一个星期几；多选生成 `MM HH * * D,D` |
| 重复 = 每月 | 必选 HH:MM + 1–31 日单选；cron = `MM HH D * *` |
| 重复 = 自定义 | 5 字段 cron 必填，前端正则粗校验 + 提交后以后端 parseCron 错误为准；支持 @hourly 等别名 |
| 有效期 = 自定义 | 起止日期均必填、start <= end（同日允许）；start 为当日 00:00、end 为当日 23:59:59（本地时区）；end 早于当前时间时提交前警告「任务创建后立即过期」 |

- 弹窗底部：取消 / 确定；确定时统一走一次前端校验，失败项内联红字提示，不提交。
- 「消息推送到企业微信」开关：确认省略，不做。

## 6. 验收标准

1. 列表页三个 Tab 计数与实际任务状态一致，切换筛选即时生效。
2. 用「每天 09:00」创建的任务，cron.json 中 cron 为 `0 9 * * *`，卡片描述显示「每天 09:00」，倒计时与 next_run_at 一致。
3. 每周/每月模式未选星期/日期时无法提交，有内联提示。
4. CLI 手工创建的 `*/15 8-18 * * 1-5` 任务在列表原样展示表达式；点编辑进入自定义 cron 模式且原值回填。
5. 权限选「允许完全访问」的任务运行时，cron-executor spawn 参数含 `--permission yolo --yolo`（单测断言 args）；「只读」对应 `--permission plan`；默认任务不传 permission flag。
6. validUntil 已过的任务：调度轮询静默跳过执行，但 nextRunAt 仍按 cron 相位正常推进（runner 单测覆盖窗口前/窗口内/窗口后三态，断言窗口外跳过后 nextRunAt 继续前移）；手动「立即运行」仍可执行。
7. POST/PATCH 传非法 permission 或 start>end 的有效期返回 400 且带可读 message。
8. 旧版 cron.json（无新字段）加载后行为等同「长期有效 + 标准确认」，读写不丢原有字段。
9. 批量管理：勾选多个任务执行「停用」「删除」后列表与 cron.json 状态一致；删除有二次确认。
10. 既有 36+6 例 F-22 单测与 cron-server 测试全部保持绿色；新增字段有对应单测。
