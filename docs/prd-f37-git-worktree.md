# F-37 git 分支切换 + Worktree 会话级隔离 —— PRD 增量

> 状态：待评审 ｜ 日期：2026-10-24 ｜ 关联：docs/PRD.md §3.2 F-37、F-24（git 集成 / 文件变更管理）、F-23（权限模式）、F-30（沙箱）

## 1. 需求回顾

范围（已与用户对齐）：**CLI TUI + Web 控制台双端**，核心逻辑落 core 供两端复用。对齐参考产品（WorkBuddy）底栏交互：底栏展示「项目文件夹 + 当前分支 + Worktree 开关」；切换分支 / 勾选 Worktree 时自动 `git worktree add` 出独立目录并把**当前会话**的工作根切过去，任务互不干扰，可随时切回主工作区。分支选择是**会话内的 checkout**（影响当前会话工作根），不是全局切换。

现状痛点（实现前）：

- `packages/core/src/git/repo.ts` 的 GitIntegration 只有 off/suggest/auto 三档提交策略与建分支（`checkout -b`），**无分支切换、无 worktree 概念**。
- 会话启动时以 `process.cwd()` 为 projectRoot 且**终身绑定**：所有 fs/exec 工具沙箱（`resolveInSandbox(ctx.projectRoot)`）、ShellAdapter cwd、hooks cwd、GitIntegration、提示词 L2 Environment 全部以此为根，无法在会话中途变更。
- 同一仓库想并行处理两个任务（如「修 bug」与「升级依赖」），只能开两个项目或排队，改动互相污染。

## 2. 产品目标

| # | 目标 | 衡量标准 |
|---|------|----------|
| G1 | 会话级工作区隔离：分支切换与 worktree 创建/切回全程不干扰其他会话与用户主工作区 | 切换后旧会话与新会话的文件读写互不可见对方改动；主工作区状态（未提交改动）在切换往返后保持不变 |
| G2 | 双端一致的底栏交互：项目名 + 当前分支 + Worktree 开关一屏可见、一步可达 | TUI 底栏与 Web 底栏均常驻三段式状态；分支切换 ≤ 2 步操作 |
| G3 | 核心逻辑单点沉淀：分支/worktree 管理全部在 core，CLI/Web 仅做交互壳 | 两端无各自实现的 git 调用；切换语义（安全规则、命名、事件）单一来源 |

| F-37-3 | 切换安全规则 | ① 会话运行中（任务未结束）禁止切换，UI 置灰并提示；② 主工作区切分支时若工作区脏（isDirty）则阻止并提示先提交/stash，**不自动 stash**；③ worktree 切换（add 新目录）不受脏工作区影响（新目录从分支 HEAD 干净检出）；④ 提示词 L2 Environment 层随切换重组装（CWD 更新） |
| F-37-4 | worktree 目录约定 | 存放在**仓库外**避免嵌套：`../<repoName>.worktrees/<sessionId 前 8 位>`（名字形如 `yzero-a1b2c3d4`）；会话与 worktree 目录一一绑定（勾选→创建并切换，取消→切回主工作区，目录保留）；会话持久化记录绑定的工作根，恢复会话时还原绑定 |
| F-37-5 | TUI 底栏 | 底栏三段式：左侧项目名 ｜ 中间当前分支（`/branch` 或快捷键弹出分支选择列表：方向键选择/回车切换/`n` 新建）｜ 右侧 Worktree 开关（`/worktree` 或快捷键切换）；切换结果以行内提示反馈（成功/失败原因） |
| F-37-6 | Web 底栏 | 对话页底部状态条同样三段式：项目名 ｜ 当前分支（点击弹出分支下拉：本地分支列表 + 当前打勾 + 新建输入框）｜ Worktree checkbox（勾选即切入、取消即切回）；切换通过 hub 转发 core 执行，结果以 toast 反馈 |
| F-37-7 | 与 GitPolicy 衔接 | GitPolicy（off/suggest/auto）语义不变：suggest 启动建议文案与底栏分支信息联动；auto commit 在**当前工作根**执行（worktree 内的会话提交的就是 worktree 里的改动）；F-24 FileChangeStore 相对路径以**当前工作根**为基准，回滚同样作用于当前工作根 |

## 5. 关键交互说明

### 5.1 CLI TUI（packages/cli）

```
┌──────────────────────────────────────────────────────┐
│  （消息流…）                                          │
├──────────────────────────────────────────────────────┤
│ my-app │ ⎇ main              │ ☐ Worktree            │  ← 底栏常驻
└──────────────────────────────────────────────────────┘
```

- 底栏左：项目名（已注册项目名）；中：当前分支（detached HEAD 显示短 hash）；右：Worktree 开关（☐ 主工作区 / ● 已切入 worktree）。
- `/branch`：弹出分支列表卡（ink 选择卡，与确认卡同风格）——方向键选择、回车 checkout、`n` 输入名称新建并切过去、`Esc` 取消；运行中打开提示「任务运行中，结束后再切换」。
- `/worktree`：开关注册——勾选路径：脏不拦截（新目录干净检出），创建成功后底栏右侧变 ●，行内提示目录路径；取消路径：切回主工作区，提示「worktree 目录已保留，可用 yzero worktree remove 清理」。
- 切换成功后向会话注入系统提示一行：`[环境] 工作根已切换：<分支> @ <目录>`。

### 5.2 Web 控制台（packages/web）

- 对话页底部状态条（输入框下方）同样三段式，样式对齐 TUI 语义。
- 分支下拉：点击分支名弹出浮层——本地分支列表（当前打勾、按字母序）、底部「+ 新建分支」输入框；hub 转发 `core` 执行，成功后状态条即时刷新。
- Worktree checkbox：勾选触发 `worktree add` 并切换；取消触发切回；运行中 checkbox disabled；切换中显示 loading，结果 toast 反馈（成功带目录路径，失败带原因）。
- 会话列表/恢复：绑定 worktree 的会话在列表项加轻量标识（如 🌿），重开自动还原绑定。

## 6. 与现有机制的关系（增量边界）

| 机制 | 关系 |
|------|------|
| GitPolicy（off/suggest/auto） | **不改语义**。suggest 建议文案继续生效；auto commit 切换后跟随当前工作根（见 F-37-7）。GitIntegration 增加 projectRoot 可变注入（构造参数改为 getter 或 update 方法），行为不变 |
| 权限模式（plan/default/yolo） | **不变**。切换分支/worktree 是用户显式 UI 操作，不走工具确认流；plan 模式下同样允许切换（只改工作根，不写代码）；运行中禁切规则对三模式一致 |
| 沙箱（F-30 / resolveInSandbox） | **跟随工作根**：沙箱根 = 当前工作根。worktree 目录本身即为合法沙箱根（用户显式创建），不视为逃逸；Seatbelt 参数中的项目路径随切换更新 |
| F-24 文件变更管理 | FileChangeStore 相对路径基准、`/changes`、`/rollback` 均作用于当前工作根；切回主工作区后历史变更快照中的相对路径以主工作区解析（快照保留绝对路径辅助字段以便核对） |
| 会话存储 | sessions 表增加工作根绑定字段（分支 + worktree 路径 + 是否 worktree），迁移走 F-35 机制（v4） |

## 7. 待确认问题

| # | 问题 | 建议 |
|---|------|------|
| 1 | worktree 目录存放位置是否需要可配置？ | 一期固定 `../<repoName>.worktrees/<sessionId8>`（仓库外、防嵌套），P2 再配置化（F-37-13） |

| 3 | 切回主工作区时 worktree 目录是否自动删除？ | 默认保留（防误删未提交工作），提供显式 remove 入口（F-37-8） |
| 4 | 切换是否允许在「任务运行中但模型空闲等待确认」的间隙进行？ | 不允许，统一规则「运行中禁切」，实现简单、语义无歧义 |

## 8. 范围外（本期不做）

- 远端分支的 fetch / push / pull（分支列表仅本地分支；push 仍由用户手动或既有 auto commit 流程负责）
- 模型自主发起的分支切换/新建（仅 UI 用户操作，P2 只读工具除外）
- worktree 内自动依赖安装、自动跑构建（P1 仅提示，F-37-10）
- 同一仓库多项目注册时的 worktree 归属仲裁（沿用现有项目注册假设：一仓库一项目）
- git worktree 之外的隔离方案（如 docker 容器内 clone）
